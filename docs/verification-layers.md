# Verification layers and planted bugs

## Layers

The specification is executable: [`model/isa.ml`](../model/isa.ml) is a reference
model written for clarity, with no dependency on the hardware, so the two
cannot share a bug. Everything else is checked against it or against
independent protocol oracles.

| Layer | What is checked | How |
|---|---|---|
| ISA encoding | all 65,536 instruction words | exhaustive encode/decode and disassemble/assemble round trips |
| Firmware | UART TX on the model | cycle-exact against an ideal waveform, plus a mid-bit-sampling receiver, over random bytes and baud rates |
| Core RTL | `hw/pe_core.ml` against the model | lockstep differential test: 400 random programs × 300 cycles, both threads with random configs, random pins, host traffic on both threads, threads enabled and disabled at random, and the host rewriting the packet buffer's and the bit sampler's registers as a trial runs; the full state of both threads, the buffer's pointer, every register of the sampler and the pins compared every cycle |
| Two threads | demo images on the model and the chip | SPI and UART running together, each judged by its own oracle; isolation: the SPI waveform is identical, cycle for cycle, whether or not the UART thread runs; the bridge: an I2C read (checked by the I2C oracles) comes out as one SPI transfer (checked by the SPI oracles), with the host never touching the data |
| Whole chip | `hw/top.ml` through its pins only | bit-banged SPI host: register read-back, echo firmware through both FIFOs, UART firmware decoded on the pin |
| Protocols | UART, I2C, SPI firmware | independent protocol oracles on the pins: UART waveform + receiver, and an off-rate frame generator (fractional bit times) driving the UART receiver; I2C bus checker + target device that ACKs and stretches SCL; SPI mode-0 checker + slave with scripted responses |
| Coverage closure | 16 cross bins random testing reaches rarely | 19 AI-written directed scenarios, each judged by the same lockstep comparison and required to hit its own targets; they close every cross bin and catch every one of the 33 planted RTL bugs ([`docs/coverage-closure.md`](coverage-closure.md)) |
| Device mode | the I2C and SPI device firmware, on the model and the chip | the spec-derived reference controller (with one clock of data hold time and with none, 7 to 62 clocks of SCL low) writing, reading and register-reading through a repeated START, judged by the bus checker; a shared bus where the chip must ignore a model device at another address; the host late on both FIFOs so the chip must stretch; two model chips talking, the controller firmware on one and the target on the other; the whole chip over SPI. For SPI, the same with a spec-derived mode-0 controller, with and without gaps between bytes, a transfer abandoned mid-byte, and two chips (controller and device firmware) on four wires |
| Host driver | `host/protocol_emulator.py`, the MicroPython code the demo board runs | the same file, unchanged, run against the chip in cocotb (on the RTL and the gate-level netlist): it loads firmware and configures threads over the bit-banged host port, sends UART to cocotbext-uart's receiver, reads picosoc's SPI flash, and serves cocotbext-i2c's and cocotbext-spi's controllers as an I2C and an SPI device. Then in MicroPython itself, on an emulated demo board (rp2040js running Tiny Tapeout's firmware) wired to the RTL: UART, I2C, SPI, JTAG, SWD and USB against the same devices (1-Wire's driver runs there on a simulated bus; PS/2 and CAN do not run there yet), and the USB descriptor read with every handshake timed on the bus (`test/board_emu`) |
| SWD | the clock engine and the driver's framing | an SWD target written from Arm's ADIv5 (`test/swd_dp.v`), in cocotb on the RTL and the gate-level netlist: silent until the JTAG-to-SWD switch, then DPIDR, a power-up request acknowledged, an AP's IDR through a posted read and RDBUFF, an AP register written and read back; on the model, 300 random sequences checked against the engine's contract |
| 1-Wire | the bus engine and the driver's ROM layer | on the model: 360 random runs of resets and time slots with zero to three devices, each drawing its timing at random from the range the 1-Wire rules allow (sample point, how long a 0 is held, the presence pulse's delay and length), checking the bits both ways and the host's own pulse timing against the rules. In cocotb, against three copies of Iztok Jeras's 1-Wire slave model (sockit_owm, third-party, LGPL, test only) at the shortest, typical and longest legal timing, with a DS18B20's ROM and function layers above them: each device's ROM code and temperature alone, and with all three on one wire the ROM search finds every device and MATCH ROM reaches each. In MicroPython, the driver's search and CRC on a simulated bus agree with CPython's |
| PS/2 | the host firmware on both threads, and the driver | on the model: 150 random runs of traffic both ways against a device written from the protocol's rules, with its timing drawn at random from the legal range (clock phases, data setup, the delay before it clocks a host byte) and the host cutting in at the start of the device's frames and in the middle of them; every byte arrives exactly once each way, the receiver's record of the host's own byte matches, and the host's pulses meet the rules (100 us of CLK low to inhibit, DATA changed only while CLK is low). A device that does not acknowledge, and no device at all, are reported. In cocotb, on the RTL and the gate-level netlist, the driver resets and identifies a keyboard, sets its LEDs and reads a key press and release |
| CAN | the node (transmitter and receiver), and the driver | on the model: 120 random runs against a second node written from ISO 11898-1's rules, with its own clock up to 1.25% off, which hard-synchronises and resynchronises, removes stuff bits as they come, checks the CRC, acknowledges good frames, sends frames of its own and counts the acknowledgements it gets; in half the runs it starts in the same bit as the chip, so the two arbitrate. Every frame reaches the other side intact, each side acknowledges every one of the other's frames, the chip does not receive its own, the loser of each arbitration stops without disturbing a bit and sends again, every bit the chip sends is exactly one bit time, and with no node the chip reports that nobody acknowledged. The stuffing and the CRC are the chip's in both directions: the node removes the stuffing and computes the CRC its own way. Thirteen frames go to the node one at a time for the transmitter's corners: every length from 0 to 8 bytes, and a stuff bit that falls after the last bit of the data or of the CRC, at each level. A frame with a wrong CRC is not acknowledged and is marked bad, and the frame right behind it is taken; a remote frame, a length code above 8 and an extended frame (left alone) each go through; while a host takes no words the frames that arrive go unacknowledged, and the receiver is back when it listens again. Forty more random runs each at 20 and at 40 core clocks a bit, with the node on the chip's clock. The model's CRC is checked against CRC-15/CAN's catalogued check value. In cocotb, on the RTL and the gate-level netlist, the driver and a node exchange frames while sigrok's CAN decoder reads the bus and must report both frames with their CRCs and ACK; the chip does not acknowledge the node's frame with a wrong CRC; alone on the bus the chip's frame goes unacknowledged |
| Outside decoders | SWD, PS/2 and CAN, whose device models are this project's own; USB and 1-Wire beside their device models; WS2812, which had none | in cocotb, the pins are recorded and handed to sigrok's protocol decoders (`test/sigrok.py`): the whole SWD session, request by request with every ACK and data word; both CAN frames with identifier, data, CRC and ACK slot (each side acknowledges the other's frame); every PS/2 frame both ways. In each, one bit is then forced on the recorded wire and the decoder's verdict must change. The engines added on v2.0 (I2S, DMX512, Wiegand, NEC and RC-5 infrared, DALI, MDIO, PWM, the NES gamepad) and the device protocols on existing engines (MIDI, MAX7219, LIN, Modbus RTU, 24Cxx EEPROM, DS1307, LM75, SPI NOR flash, WS2801) are judged the same way: sigrok's decoder must read back exactly what the host asked for, and in all but the DS1307 and PWM tests the recording is damaged once and the reading must change. Seven more devices run on the SPI controller with a scripted device answering (nRF24L01, CC1101, RFM12 and MRF24J40 radios, the ENC28J60, the ADF435x, an SD card's first commands): sigrok's decoder for each must name every command and read the bytes that came back, and one damaged field must disappear. The USB enumeration goes to sigrok's three USB decoders, which check each packet's CRC and name the request; the 1-Wire sessions to its link and network decoders, which read the ROM; and the WS2812 driver that was written blind, loaded on the chip with its own encoder, to sigrok's WS281x decoder, which must read both colours. That is 31 tests in all. MDIO also reads from a PHY written from IEEE 802.3, the gamepad from a shift register written from its data sheet, and the I2C and SPI devices from cocotbext-i2c's memory and picosoc's flash |
| v2.0 engines, on the model | the eleven engines written on v2.0 (`sim/test_tx_engines.ml`) | each transmitter's pins decoded by a receiver written from the protocol's rules, and each receiver fed by a source written from them: Wiegand pulses down to a microsecond, NEC remotes from 23% slow to 23% fast, frames cut short and repeat codes; PWM compared to the cycle |
| Ethernet transmit | `eth_tx`, the packet buffer, autopull and the CRC register (`sim/test_ethernet.ml`) | on the model: frames of 60 to 1514 bytes, odd lengths included, decoded by a receiver written from IEEE 802.3 that checks the preamble, every Manchester cell to the clock, the frame check sequence by its own CRC and the start of idle; the CRC register against the published check values of CRC-32, CRC-16/USB and CRC-15/CAN. In cocotb, on the RTL and the gate-level netlist at a 40 MHz clock: the driver sends an ARP request, an odd-length frame and one of 1514 bytes, judged by a receiver whose CRC-32 is `zlib`'s |
| Ethernet receive | `eth_rx` and the bit sampler (`sim/test_ethernet_rx.ml`) | on the model: a sender written from IEEE 802.3 whose times are in nanoseconds and owe nothing to the chip's clock; frames of 60 to 1514 bytes; the sender 100 ppm off, and 5,000; the two clocks at 200 alignments across a cycle; frames 9.6 us apart; a wrong frame check sequence told apart; link pulses and noise recording nothing; thread 1 receiving what thread 0 sends; and a sweep of jitter on every edge, which measures the limit (every frame good to 6 ns at 40 MHz and 10 ns at 50 MHz, against the 13.5 ns the standard asks of a receiver). The sampler alone on NRZ data from a sender 2% off. Through the host port in the OCaml simulator. In cocotb, on the RTL and the gate-level netlist: four frames from a sender 100 ppm off with every edge up to 5 ns early or late, landing between clock edges; one has a wrong frame check sequence |
| Driver size | `host/protocol_emulator.py` and `host/more_protocols.py` on the board's microcontroller | both compiled and run by MicroPython on the emulated RP2040 (`test/board_emu/run_compat.mjs`), every driver class exercised against a recording chip and compared with CPython; this is the check that found the single driver file had outgrown the board's memory |
| USB | the low-speed engine and the driver's packets | on the model: the encoder reproduces captured USB packets; 150 random batches of sent packets decode at a reference receiver written from the USB 1.1 spec and match the ideal waveform to the clock; 300 received packets from a device whose clock is up to 1.5% off either way; whole IN transactions with the ACK 2 to 7.5 bit times after the data, as the spec requires. In cocotb, against usbhostslave's USB device (third-party, LGPL, test only): SETUP acknowledged, a corrupted CRC16 ignored, and a full GET_DESCRIPTOR control transfer whose 18 bytes match the device's ROM |
| Third-party devices | the chip against device models written by other people from real datasheets | picosoc's Verilog SPI flash (wake, then a 0x03 read at a 24-bit address), cocotbext-i2c's I2C EEPROM (write, pointer set, read back), cocotbext-uart's UART sender and receiver, and, with the roles reversed, cocotbext-i2c's I2C controller driving the chip as a device at 400 kHz (probe, a write that makes it stretch the clock, a register read through a repeated START), cocotbext-spi's SPI controller reading the chip as a device (a JEDEC ID read and a command), and cocotbext-jtag's monitor decoding every scan while the chip, as a JTAG controller, reads an IEEE 1149.1 device's IDCODE, writes and reads back a register and goes through BYPASS; on the RTL and the gate-level netlist |

| **Formal, the memory** | the flip-flop description of a program memory that the OCaml tests and both other proofs use, against IHP's behavioural model of the SRAM macro | **Yosys equivalence proof** in CI ([`formal/sram_equiv.py`](../formal/sram_equiv.py)): both sides are generated from the one function the chip is built from, so the macro is tied off as the chip ties it; all 256 words and the output register take the same next value for every state and input. One planted bug (the output not held on a write cycle) must break it. The packet buffer's 1,024-word memory is proved against IHP's model of its macro the same way, with the same planted bug. Not shown: that the silicon macros behave as IHP's models say |
| **Formal, RTL to gates** | the post-layout netlist against the generated Verilog | **Yosys equivalence proof** in CI after every layout ([`gl_equiv/`](../gl_equiv)): 1,538 signals paired by name (every output pin, all 1,107 flip-flops and everything driven into the three memories), a base case from any state through one reset cycle, and an induction step, so the netlist and the RTL agree on every pin from the first cycle after reset; cells modelled from IHP's Liberty file. The SRAM macros are cut out of both sides: each one's output is an arbitrary word, the same on both sides, and its inputs must be proved equal (`gl_equiv/sram_cut.v`). Five bugs planted in the netlist each break it |
| **Formal** | the whole chip RTL against an independent spec | **SAT equivalence proof** (Hardcaml_verify + Z3): one clock of the chip's top level equals one clock of [`sim/spec_top.ml`](../sim/spec_top.ml), for every state of every register and every input on the pins. The spec is a second description of everything: the SPI host port and register file (written from the protocol and register map in `hw/top.ml`'s header, with the map as a table and reads as one-hot terms), around [`sim/spec_core.ml`](../sim/spec_core.ml) (program memory, input synchronisers, pin levels, clock dividers, FIFOs, CHAIN, the packet buffer's control, the bit sampler, pin priority, pads, from the ISA document and the reference model), with [`sim/spec_step.ml`](../sim/spec_step.ml) as each thread's datapath, which itself matches the reference model on all 65,536 instruction words. The two sides share only register names, widths, reset values and the FIFO's state encoding, which the checker needs to pair registers. The packet buffer's memory is a box with nothing inside on both sides: its output is the same arbitrary word for both and its inputs must be proved equal. Bugs planted on the spec's side break the proof, so it is not vacuous |

Three practices run through all of it.

**Mutation testing, kept in the repo.** Every layer has deliberately planted
bugs, 176 in all, kept as code, and the suite fails if any survives. A test
suite that has never failed has not been shown to work.

Two oracles exist because each misses things alone. A start bit one clock
short decodes fine at a real receiver in all 300 test cases and is caught
only by the cycle-exact check.

**Functional coverage that fails the build.** The differential test counts
what the random programs actually did: every instruction, every stall, every
timeout, and both full and empty FIFOs. Any zero fails the build. Its first
run found that "PUSH stalls on a full RX FIFO" had never occurred, because the
random host drained the FIFO too often. The fix was to the test (per-trial
host behaviour), not the design.

**Generated artifacts can't drift.** CI regenerates `src/protocol_emulator.v`
from Hardcaml and fails if the committed copy differs. Firmware images for
the Python tests are assembled from the same source the OCaml tests use.

The oracles have caught real bugs, in the firmware and in themselves: SCK
idling high after reset (pins reset high; SPI mode 0 needs it low), a slave
model that dropped a preloaded response on deselect, and an I2C checker too
strict about the clock edge before STOP. The first proof attempt failed on a
difference in the RX FIFO's data wires that never reaches behaviour; the spec
now matches. See [`docs/related-work.md`](related-work.md) for the
literature this draws on.

The hardware has changed four times since v1.4: the program memory
(v2.0), the packet buffer, automatic refill and the CRC register (v2.1),
the bit sampler (v2.2), and its prescaler, pin shift and stuff-bit
removal (v2.3). Each change went in with its part of the
model, both specifications, the proofs, planted bugs and required
coverage. Everything else since is firmware, testing and documentation,
none of which can put the chip at risk.
